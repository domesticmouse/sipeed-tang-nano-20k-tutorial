## 1. Why Generated Verilog Looks Like Compiler Assembly {#big-picture}

If you open `blinky.v` and think *"I have no idea what any of this means,"* you are reacting the exact right way.

`blinky.v` is **not** hand-written Verilog. When you call `verilog.convert(...)` in Amaranth, Amaranth lowers your Python module into an intermediate hardware graph (RTLIL) and asks **Yosys** to print that graph as Verilog-2001. Just like running `gcc -S` on a clean C function produces assembly full of temporary labels (`.L2`, `%eax`), Yosys emits Verilog full of compiler-generated wire numbers (`\$1` through `\$5`), tool metadata (`(* ... *)`), and simulation helper scaffolding (`\$auto$...`).

Once you strip away the compiler punctuation, the entire 50-line file describes just **two clocked flip-flops** (`timer` and `pattern`) and **a few combinational wires** feeding them:

1. **Combinational logic** continuously watches the current voltages on `timer`, `pattern`, and `rst`, and computes two candidate next values: `\$4` (next `timer`) and `\$5` (next `pattern`).
2. **Synchronous flip-flops** (`timer` and `pattern`) wait patiently until the rising edge of `clk`, then snapshot `\$4` and `\$5` simultaneously—like two clocked sample-and-hold stages firing on the same trigger pulse.

```mermaid caption="Figure 2.1: Complete signal flow inside blinky.v — combinational wires feed two clocked flip-flops"
flowchart LR
  RST["rst (input)"] --> MUX4["\$4 (timer next-state mux, always @*)"]
  RST --> MUX5["\$5 (pattern next-state mux, always @*)"]
  TIMER["timer[23:0] (flip-flop, posedge clk)"] --> CMP["\$1 = (timer == 24'hcdfe5f)"]
  TIMER --> ADD3["\$3[24:0] = timer + 1"]
  CMP --> MUX4
  ADD3 -->|"[23:0] slice"| MUX4
  MUX4 -->|"<= at posedge clk"| TIMER
  CMP --> MUX5
  PAT["pattern[5:0] (flip-flop, posedge clk)"] --> ADD2["\$2[6:0] = pattern + 1"]
  PAT -->|"hold default"| MUX5
  ADD2 -->|"[5:0] slice"| MUX5
  MUX5 -->|"<= at posedge clk"| PAT
  PAT --> INV["assign leds = ~ pattern"]
  INV --> LEDS["leds[5:0] (output)"]
```

Every single line of `blinky.v` maps to one piece of Figure 2.1. Let's walk through all 50 lines in small blocks so nothing is left unexplained.

## 2. Reading `blinky.v` Block by Block {#block-walkthrough}

### Block 1: Comments, Synthesis Attributes, and the `module` Boundary

```verilog caption="Lines 1–5 of blinky.v: header comment, tool attributes, and module signature"
/* Generated by Yosys 0.71 (git sha1 b4c586fd3, Release, Clang /home/runner/work/amaranth-yosys/amaranth-yosys/wasi-sdk-34.0-x86_64-linux/bin/clang++ 23.1.0) */

(* top = 1 *)
(* generator = "Amaranth" *)
module blinky(rst, leds, clk);
```

- `/* ... */` is a standard C-style block comment telling you which Yosys build emitted the file.
- `(* top = 1 *)` and `(* generator = "Amaranth" *)` are **Verilog-2001 attributes**. They are not executable logic and create zero hardware gates—they are metadata tags attached to the `blinky` module so downstream tools like `yosys` and `nextpnr-himbaechel` know `blinky` is the top-level chip boundary and came from Amaranth.
- `module blinky(rst, leds, clk);` opens the hardware block (and `endmodule` on the final line closes it). Think of `module` like a schematic symbol box: `(rst, leds, clk)` lists the external pins poking out of the box, matching `leds: Out(6)` plus the automatic `clk` and `rst` pins of Amaranth's `sync` domain.

### Block 2: Port Directions, `wire` Declarations, and `[MSB:LSB]` Buses

```verilog caption="Lines 7–12 of blinky.v: non-ANSI port directions and bus bit ranges"
  input rst;
  wire rst;
  output [5:0] leds;
  wire [5:0] leds;
  input clk;
  wire clk;
```

- **Why does every pin appear twice (`input rst;` then `wire rst;`)?** Verilog-2001 supports both a compact style (`input wire rst`) and an older **non-ANSI** two-line style where the first line sets the **direction** (`input` or `output`) and the second line sets the **net kind** (`wire`, meaning a physical electrical connection rather than storage). Yosys always prints the two-line form.
- **What does `[5:0]` mean?** In C, `leds[6]` declares 6 array elements numbered `0` to `5`. In Verilog, **`[5:0]` declares a 6-bit parallel hardware bus** whose wires are indexed from **MSB (`5`) down to LSB (`0`)**: `leds[5]`, `leds[4]`, `leds[3]`, `leds[2]`, `leds[1]`, `leds[0]`. Notice that matches `leds[0]` through `leds[5]` in `tangnano20k.cst` from Lesson 0001!{{sidenote: Verilog puts the most significant bit on the left (`[MSB:LSB]`) because binary numbers are written MSB-first on paper (`6'b100000` has bit `5` equal to `1` and bit `0` equal to `0`).}}

### Block 3: Escaped Identifiers, Carry-Preserving Widths, Sized Literals, and the `reg` Trap

```verilog caption="Lines 13–19 of blinky.v: internal wires, next-state muxes, and clocked registers"
  wire \$1 ;
  wire [6:0] \$2 ;
  wire [24:0] \$3 ;
  reg [23:0] \$4 ;
  reg [5:0] \$5 ;
  reg [5:0] pattern = 6'h00;
  reg [23:0] timer = 24'h000000;
```

Four dense Verilog rules live in these seven lines. Unpacking them makes almost all Yosys output immediately readable:

1. **Escaped identifiers (`\$1 `):** Normal Verilog names can only use letters, digits, `_`, and `$` (and cannot start with a digit or `$`). When Yosys wants an internal temporary name like `$1`, it uses Verilog's **escaped identifier** rule: start with a backslash (`\`) and end at the **first whitespace character**. That is why `\$1 ;` has a mandatory space before the semicolon! Read them with human nicknames:
   - `\$1` = `timer_expired` (1-bit flag: did `timer` hit $13{,}499{,}999$?)
   - `\$2` = `pattern_plus_1` (7-bit result of `pattern + 1`)
   - `\$3` = `timer_plus_1` (25-bit result of `timer + 1`)
   - `\$4` = `timer_next` (24-bit candidate next value for `timer`)
   - `\$5` = `pattern_next` (6-bit candidate next value for `pattern`)
2. **Why is `\$2` 7 bits (`[6:0]`) and `\$3` 25 bits (`[24:0]`)?** Suppose `pattern` is `6'b111111` ($63$). Adding `1` gives `7'b1000000` ($64$), which needs a 7th carry bit! Unlike C—which silently throws away overflow on unsigned addition of fixed-width integers—Amaranth preserves the carry bit during `+` (`6` bits `+ 1` = `7` bits in `\$2`; `24` bits `+ 1` = `25` bits in `\$3`), and then explicitly slices off the bottom bits (`[5:0]` and `[23:0]`) when storing back into the register.
3. **Sized literals (`<width>'<base><value>`):** `6'h00` means a **6-bit** (`6`) **hexadecimal** (`'h`) value equal to `00` (all zeros). You will also see `'b` for binary (`6'b111111`) and `'d` for decimal (`6'd63`). On line 24, `24'hcdfe5f` is the 24-bit hex number $0\text{xCDFE5F} = 13{,}499{,}999$—which is `self.half_period - 1` ($13{,}500{,}000 - 1$).
4. **The `reg` trap (`timer`/`pattern` vs. `\$4`/`\$5`):** Beginners naturally assume `reg` always means "hardware flip-flop register." **It does not!** In Verilog, `reg` is just a grammar keyword meaning *"a variable assigned inside an `always` block."*
   - `pattern` and `timer` (`= 6'h00` / `= 24'h000000` power-on reset initializers) *are* real D flip-flops because they are assigned inside `always @(posedge clk)`.
   - `\$4` and `\$5` are **pure combinational multiplexers** (zero flip-flops!)—they are only declared `reg` because Yosys assigns them inside `always @*` blocks.

### Block 4: Clocked Flip-Flops (`always @(posedge clk)` and Non-Blocking `<=`)

```verilog caption="Lines 20–23 of blinky.v: synchronous D flip-flops updating on the rising clock edge"
  always @(posedge clk)
    timer <= \$4 ;
  always @(posedge clk)
    pattern <= \$5 ;
```

- `always @(posedge clk)` means *"synthesize edge-triggered D flip-flops clocked by the rising (`0` → `1`) edge of `clk`."* Nothing in hardware happens between edges; the registers simply hold their voltage steady.
- `<=` is Verilog's **non-blocking assignment**, which directly implements Amaranth's `m.d.sync +=`. Think of `<=` as a **two-phase snapshot**: at the exact rising edge of `clk`, every `<=` statement across the entire chip samples its right-hand side (`\$4` and `\$5`) *first*, and only *then* updates `timer` and `pattern` simultaneously. Even if `timer` and `pattern` read each other, neither steals the other's new value mid-clock.

### Block 5: Continuous Combinational Wires (`assign`)

```verilog caption="Lines 24–27 of blinky.v: permanently wired combinational gates"
  assign \$1  = timer == 24'hcdfe5f;
  assign \$2  = pattern + 1'h1;
  assign \$3  = timer + 1'h1;
  assign leds = ~ pattern;
```

- `assign` creates **continuous combinational hardware** (matching `m.d.comb` and inline expressions in Amaranth). Just like four analog op-amp stages soldered onto one board, all four `assign` lines run **simultaneously and continuously**:
  - `\$1` is a 24-bit equality comparator checking whether `timer == 13_499_999`.
  - `\$2` is a 7-bit adder computing `pattern + 1` (`1'h1` is a 1-bit `1`).
  - `\$3` is a 25-bit adder computing `timer + 1`.
  - `leds = ~ pattern` is six parallel logic inverters (`~` is bitwise NOT) driving the active-low LED pins.

### Block 6: Combinational Next-State Muxes (`always @*`, Blocking `=`, and the `$auto$` Guard)

```verilog caption="Line 6 and lines 28–47 of blinky.v: combinational next-state multiplexers"
  reg \$auto$verilog_backend.cc:2542:dump_module$1  = 0;
  ...
  always @* begin
    if (\$auto$verilog_backend.cc:2542:dump_module$1 ) begin end
    (* full_case = 1 *)
    if (\$1 ) begin
      \$4  = 24'h000000;
    end else begin
      \$4  = \$3 [23:0];
    end
    if (rst) begin
      \$4  = 24'h000000;
    end
  end
  always @* begin
    if (\$auto$verilog_backend.cc:2542:dump_module$1 ) begin end
    \$5  = pattern;
    if (\$1 ) begin
      \$5  = \$2 [5:0];
    end
    if (rst) begin
      \$5  = 6'h00;
    end
  end
```

This is the part that scares everyone on first sight—and it breaks down cleanly into five simple pieces:

- **What is `\$auto$verilog_backend.cc:2542:dump_module$1  = 0;`?** That terrifying line is a **Yosys simulation quirk, not hardware**. In Verilog simulators, `always @*` normally only runs when a signal inside it *changes*. Because `always @*` has no `if` conditions guaranteed to fire at $t=0$ if inputs never toggle, Yosys inserts a dummy variable initialized to `0` and checks `if (dummy) begin end` (which does nothing) to force Verilog simulators to evaluate the block at simulation startup. Because the flag is a constant `0`, `yosys` synthesis optimizes both lines away to **zero logic gates**.
- **What is `always @*` and `begin ... end`?** `@*` is a wildcard sensitivity list meaning *"re-evaluate this combinational logic whenever any input signal read inside changes."* `begin` and `end` are simply Verilog's curly braces `{` and `}` around a multi-line block.
- **Why does `always @*` use `=` instead of `<=`?** Single `=` is **blocking assignment** (top-to-bottom priority evaluation within one combinational circuit). Yosys uses `=` here so later `if` statements can override earlier defaults—building a **priority multiplexer** where the **last matching assignment wins**:
  1. In the `\$4` block (`timer_next`): `(* full_case = 1 *)` tells the synthesizer the `if (\$1 ) ... else ...` covers all cases. If `\$1` (`timer == 13_499_999`) is true, `\$4` becomes `0`; otherwise it takes `\$3 [23:0]` (the lower 24 bits of `timer + 1`, discarding the unused carry bit). Finally, `if (rst)` sits at the very bottom: whenever button `S1` (`rst == 1`) is pressed, it overrides everything above and forces `\$4` to `0`.
  2. In the `\$5` block (`pattern_next`): Notice `\$5 = pattern;` comes **first**! In combinational `always @*` blocks, if a path forgets to assign `\$5`, Verilog would synthesize an unintended **level-sensitive latch** to remember the old value. Putting `\$5 = pattern;` at the top sets the default ("keep holding the current `pattern`"), `if (\$1 )` overrides it with `\$2 [5:0]` (the lower 6 bits of `pattern + 1`, wrapping `63 + 1` cleanly back to `0`), and `if (rst)` overrides both with `6'h00`.{{sidenote: Look at how cleanly that mirrors Amaranth: in `m.d.sync`, signals hold their value automatically unless assigned; Yosys makes that hold explicit by writing `\$5 = pattern;` at the top of the combinational mux!}}

### Block 7: The Exact Same Circuit with Human Names

If you rename `\$1`–`\$5` to English names and hide Yosys's `$auto$` dummy line, here is the entire `blinky.v` circuit you just learned to read:

```verilog caption="Conceptual translation of blinky.v with human-readable signal names"
module blinky(input clk, input rst, output [5:0] leds);
  reg [23:0] timer   = 24'h000000;
  reg [5:0]  pattern = 6'h00;

  wire        timer_expired  = (timer == 24'hcdfe5f); // 13,499,999
  wire [24:0] timer_plus_1   = timer + 1'h1;
  wire [6:0]  pattern_plus_1 = pattern + 1'h1;

  reg [23:0] timer_next;
  reg [5:0]  pattern_next;

  always @* begin
    timer_next   = timer_expired ? 24'h000000 : timer_plus_1[23:0];
    pattern_next = timer_expired ? pattern_plus_1[5:0] : pattern;
    if (rst) begin
      timer_next   = 24'h000000;
      pattern_next = 6'h00;
    end
  end

  always @(posedge clk) begin
    timer   <= timer_next;
    pattern <= pattern_next;
  end

  assign leds = ~pattern;
endmodule
```

Every line of Yosys's `blinky.v` is just the compiler-expanded version of those 26 lines!
